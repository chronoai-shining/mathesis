# Mathesis P0–P3：运行与数学质量验收交接

截至 2026-10-16，当前交付覆盖 Mathesis 下游消费、审稿门、有限计算、私有研究义务、绑定贡献与授权提案。逐项实现、测试、CI 和合并凭据见 [CAPABILITY_DELIVERY.md](CAPABILITY_DELIVERY.md)。本文件列出尚需真实资源或参与者的验收条件；代码测试中的账户、授权、审计替身和上游响应均不计为这些条件的完成证据。

## 已有读数与限制

- 固定来源含 158,749 条声明、8,673 个模块和六项明确的源文件省略。声明、源码、冻结节点、索引和运输包身份分别保留。
- 固定评估集有 18 个作者编制的案例，按定理家族分为 12 个开发样本和 6 个留出样本。标签仍为带论证的临时转录，未经人工裁定。
- 完整索引的开发集精确来源集合召回由原始词法查询的 0/12，提高到标识符、路径与标准术语方法的 10/12（前 6 或前 10 个候选）。这不等于审稿正确率。
- 原有两组 Oracle 读数在共同可用的 11 个样例上归一化判断完全相同。检索召回的改善尚未建立完整 Oracle → CMA 审稿质量改善。
- `projection_amgm-original` 的固定有限输入经 Rust 重放和独立有理数运算得到 −8/243。带该证据的单样本 Oracle 诊断由 `open / content` 变为 `known_false / undetermined`，两次实际模型均为 `gpt_6 / pro`。该观察另存，不能并入原始 12 案例读数、替代完整审稿或推断总体改善。
- 留出集未用于模型调用、检索调优或提示词调整。其正式验收仍须先固定候选版本、标签与目标。

## 恢复执行顺序

1. 确定运行目标与可执行公司 CMA 资源，保存只读预检结果；确认当前知识源已在目标环境导入且身份匹配。
2. 对一个已授权真实稿件完成 Oracle → CMA → 私有报告/决定，并保留换名、缺失假设、查询故障三个纵向案例的独立证据。
3. 固定质量验收候选和经裁定标签，预登记目标后才使用留出集。先报告各指标的分子、分母、失败和成本缺失，再判断是否达标。
4. 在真实作者与外部贡献者参加后完成研究义务及绑定贡献验收。上游能力或真实发布到达后，再完成覆盖升级和授权回流观察。

每一步都追加事实与凭据。GitHub issue 关闭、合并成功、一个模型判断改变或测试中的授权事件，均不替代上述运行与数学质量证据。
